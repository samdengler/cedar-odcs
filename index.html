Design notes

cedar-osdc

Data governance for agent tool calls, enforced with Cedar policies derived from Open Data Contract Standard documents. One design document per iteration; each iteration lives in its own directory with its policies, entities, and test corpus.

Start with the iteration 1 design narrative. It covers the problem, where Cedar sits in the stack, Cedar concepts, and a walkthrough of the code in bola-reads/.

Growing by tests

Every iteration grows the same way: test cases are added to a JSON corpus describing the next rule, they fail, and then the policies or facts that make them pass are written. Attacks are recorded before defenses, so a later change that weakens a defense fails a test. The corpus is engine-independent data in the cedar-integration-tests format, so the Python iterations and the eventual Rust enforcement build are held to identical rules. Each iteration carries its predecessors' corpora as a regression gate, each iteration is small, and no iteration starts before the previous one is understood.

Iterations

  1. Broken object level authorization (BOLA) on reads Object level checks, default deny. Code in bola-reads/. Done
  2. BOLA on writes The ownership rule gated on the request leg; a denied write rejects the whole call. Code in bola-writes/. Done
  3. Broken object property level authorization (API3) on reads Per-field decisions, strip denied fields from responses. Code in field-reads/. Done
  4. API3 on writes (mass assignment) Per-field checks on write payloads; any denied field rejects the call whole. Code in field-writes/. Done
  5. Function level (API5) Actions permitted only to roles. Planned
  6. On behalf of access modes Customer direct, employee direct, employee acting for a customer. Planned
  7. ODCS as source of truth Generate the Cedar schema and field classifications from a data contract. Planned
  8. Provable composition Prove combined policy sets preserve each iteration's guarantees; equivalence and non-interference in CI. Per-iteration proofs run in analysis/. Planned
  9. Row filtering List endpoints return only rows the caller may see. Planned
  10. Enforcement placement Move the checks into the Gateway response interceptor. Planned
