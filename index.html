Design notes

cedar-osdc

Data governance for agent tool calls, enforced with Cedar policies derived from Open Data Contract Standard documents. One design document per iteration; each iteration lives in its own directory with its policies, entities, and test corpus.

Start with the iteration 1 design narrative. It covers the problem, where Cedar sits in the stack, Cedar concepts, and a walkthrough of the code in bola-mvp/.

  1. Broken object level authorization (BOLA) Object level checks, default deny. Code in bola-mvp/. Done
  2. Broken object property level authorization (API3) Per-field decisions, strip denied fields from responses. Code in field-filtering/. Done
  3. Function level (API5) Actions permitted only to roles. Planned
  4. On behalf of access modes Customer direct, employee direct, employee acting for a customer. Planned
  5. ODCS as source of truth Generate the Cedar schema and field classifications from a data contract. Planned
  6. Row filtering List endpoints return only rows the caller may see. Planned
  7. Enforcement placement Move the checks into the Gateway response interceptor. Planned
